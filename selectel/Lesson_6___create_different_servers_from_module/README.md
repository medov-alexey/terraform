# Урок 6 — Развертывание гетерогенного пула серверов в Selectel через модули Terraform

Вместо создания одинаковых виртуальных машин, данный проект позволяет гибко описывать индивидуальные параметры (ядра, память, размер диска) и сетевой статус (наличие публичного IP) для каждого сервера в изолированном файле конфигурации `vps_list.tf`.

Секреты для авторизации не хранятся в коде, а динамически подгружаются из системных переменных окружения.

## 🛠 Архитектурная структура проекта

* `auth.tf` — конфигурация провайдеров Selectel и OpenStack (настройки авторизации).
* `variables.tf` — объявление переменных для авторизационных данных.
* `vps_list.tf` — **основной конфигурационный файл инженера**. Содержит карту объектов (`map(object)`) со списком серверов и их индивидуальными характеристиками.
* `main.tf` — глобальная сетевая обвязка (приватный свитч L2, подсеть L3, интернет-роутер, SSH-ключ) и циклический вызов модуля.
* `modules/vps/` — независимый шаблон (модуль) сервера, инкапсулирующий логику динамического создания порта, диска, флейвора и условного выделения Floating IP.

## 🚀 Инструкция по развертыванию

### Шаг 1. Импорт секретов в сессию терминала
Для обеспечения безопасности учетные данные сервисного пользователя подгружаются в оперативную память текущего терминала с помощью префикса `TF_VAR_`:
```bash
source ~/terraform-selectel
```

### Шаг 2. Инициализация рабочей директории
Загрузка плагинов провайдеров для корневой системы и дочернего модуля `vps`:
```bash
terraform init
```

### Шаг 3. Валидация и планирование изменений
Проверка синтаксиса и построение карты изменений. Terraform автоматически рассчитает, сколько ресурсов нужно создать с учетом флагов `with_external_ip` для каждой машины:
```bash
terraform plan
```

### Шаг 4. Применение конфигурации (Деплой)
Развертывание сети и параллельное создание всех описанных серверов:
```bash
terraform apply
```
После успешного завершения в консоль выведется итоговая карта распределения IP-адресов (`Outputs`).

## ⚙️ Управление парком серверов (`vps_list.tf`)

Для внесения изменений вам **не нужно** править файлы сетевой логики. Откройте файл `vps_list.tf` и управляйте инфраструктурой как кодом:

### 1. Изменение аппаратных ресурсов сервера
Вы можете на лету менять параметры `ram`, `vcpus` или `disk_size`. При запуске `terraform apply` Terraform автоматически произведет ресайз машины или тома в облаке Selectel:
```hcl
"db-primary" = {
  ram              = 8192  # Увеличили память до 8 ГБ
  vcpus            = 8     # Увеличили ядра до 8
  disk_size        = 50    # Расширили системный диск до 50 ГБ
  with_external_ip = false
}
```

### 2. Управление доступом в интернет (Флаг безопасности)
Параметр `with_external_ip` управляет выделением публичного IP-адреса с помощью тернарного оператора внутри модуля:
* `true` — сервер получит Floating IP и будет доступен из интернета по SSH (подходит для балансировщиков и веб-нод).
* `false` — сервер создается **без внешнего IP** и надежно изолируется внутри приватной сети `192.168.200.0/24` (идеально для баз данных и кэша).

### 3. Добавление и удаление серверов
* Чтобы **добавить** сервер, просто допишите новый блок ключ-значение в карту `default`.
* Чтобы **удалить** сервер, сотрите или закомментируйте его блок. При этом остальные работающие серверы не будут затронуты.

## 📊 Ожидаемый результат работы (`Outputs`)

После успешного выполнения `terraform apply` вы получите наглядный отчет о доступности серверов:

```text
assigned_ip_addresses = {
  "balancer-node" = "95.213.44.12"
  "cache-server"  = "Internal Only (No WAN)"
  "db-primary"    = "Internal Only (No WAN)"
  "db-replica"    = "Internal Only (No WAN)"
  "web-prod-1"    = "95.213.44.15"
  "web-prod-2"    = "95.213.44.16"
}
```

## 🗑 Полное уничтожение инфраструктуры
По окончании лабораторной или учебной работы обязательно удалите все ресурсы, чтобы предотвратить списание средств за аренду дисков и публичных IP:
```bash
terraform destroy
```
